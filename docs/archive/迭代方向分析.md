# 优化迭代方向分析（对照 OpenCode / Claude Code / claw-code-agent）

> 目的：借鉴成熟编码 agent 的 CLI/会话/上下文管理设计，找出我们 agent 的新增功能方向，并按 spec-driven 排定落地优先级。

## 1. 参照项目调研

### 1.1 OpenCode（sst/opencode）
- 形态：**TUI 交互式 REPL**，一次启动后可连续多轮对话（非一次性 run）。
- 关键命令（参考其文档）：`/init`（初始化项目配置）、`/new`（新会话）、`/agents`（创建/管理带角色的子 agent）、`/models`（切换模型）、`/undo`、`/redo`、`/theme`、`/help`。
- 借鉴点：**会话是持久对象**（可 /new、可恢复），**subagents 角色化**，模型可在会话中切换。
- 参考：[opencode slash-commands 参考](https://github.com/wesammustafa/opencode-primer/blob/main/docs/reference/slash-commands.md)、[OpenCode 快速指南](https://raw.githubusercontent.com/clouds-anr/opencode/dev/OPENCODE_GUIDE.md)

### 1.2 Claude Code
- 形态：交互式 REPL + 大量 slash 命令，上下文管理最成熟。
- 关键命令：`/help`、`/clear`（清空上下文）、`/compact`（**显式压缩对话**）、`/model`（切换模型）、`/permissions`（管理权限）、`/memory`（跨会话记忆）、`/review`（审查改动）、`/rewind`（回退对话+代码状态）、`/status`、`/cost`、`/tokens`、`/usage`（成本/用量）、`/export`（导出会话）、`/resume`（恢复会话）、`/vim` 等。
- 上下文机制：**自动 compact**（token 逼近上限时自动摘要）+ **显式 /compact**；官方反复强调"large tool outputs 消耗大量上下文"、"会话与压缩方式比预期更影响效果"。
- 借鉴点：**/compact 是产品核心**；状态可见（/status /cost /tokens）；可回退（/rewind）。
- 参考：[Claude Code 会话管理与 1M 上下文](https://claude.com/blog/using-claude-code-session-management-and-1m-context)、[Claude Code 命令清单](https://github.com/Rigel-Computer/claude-code-docker/blob/main/docs/claude_code_commands_full_EN.md)、[官方 best practices](https://code.claude.com/docs/en/best-practices)

### 1.3 claw-code-agent（HarnessLab）
- 形态：**纯 Python、零外部依赖**的编码 agent；提供 `--tools read_file,grep_search` 这类**按需裁剪工具集**的启动参数；目录含 `agent_runtime` 等分层。
- 借鉴点：**工具按需裁剪**（只暴露任务需要的工具 → 减少模型误用、省 token）、轻量工程结构。
- 参考：[HarnessLab/claw-code-agent](https://github.com/HarnessLab/claw-code-agent)

## 2. 我们的现状（能力地图）

| 维度 | 现状 | 与成熟项目的差距 |
|---|---|---|
| CLI 形态 | 一次性 `run <task>`，非交互 | 无 REPL、无 slash 命令 |
| 会话 | 每次 run 全新历史，无持久化 | 无 /resume、无 session 文件 |
| 上下文 | 全量携带 + 启发式截断 + `summarize_oldest`（纯字符压缩） | 无 LLM 摘要、无显式 /compact、无自动触发 |
| 状态可见 | 仅 `--trace` 打印；eval 报告有 token | CLI 内无 /status /cost /tokens |
| 模型 | `--model` 参数一次性覆盖 | 无会话内热切换 |
| 权限 | 静态黑名单 + workdir 围栏 | 无交互确认、无查看/调整入口 |
| 质量 | eval 有 LLM-judge | CLI 内无 /review 自查 |
| 工具 | 8 个工具固定全量暴露 | 无按需裁剪 |

## 3. 新增功能提案（按层分级）

### A. 会话与交互层（最优先，直接改变"怎么用"）
- **A1 交互式 REPL + slash 命令框架**（P0）
  - 命令集起步：`/help`、`/exit`、`/clear`、`/compact`、`/model <name>`、`/status`、`/task`、`/review`、`/export`、`/resume`
  - 普通输入 = 给 agent 的新任务/追问（连续多轮，历史延续）
  - 实现自研（不能套框架）：输入循环、命令分发、会话状态机——正是题目要求的"对话历史与上下文管理"自研的展示机会
- **A2 会话持久化**（P1）：session 文件（消息历史+workdir+模型+token 用量），支持 `/resume <id>`
- **A3 /task 任务清单**（P1）：agent 维护显式 todo 列表（目标/当前子任务/完成项），
  - 模型可见 → 长任务不迷失；用户可见 → 进度透明
  - 与评测"任务=描述+验收"呼应：/task 让 agent 把大任务拆成可验收的小步

### B. 上下文管理（核心质量优化，对应面试"为何这样运转"）
- **B1 /compact：LLM 摘要压缩**（P0，替代纯启发式）
  - 把整段对话压缩成结构化摘要：`目标 | 已确认事实/文件 | 已完成 | 待做 | 下一步`
  - 与 `summarize_oldest` 的关系：手动触发用 LLM 摘要（保真），自动兜底用启发式（省 token）
- **B2 自动 compact**（P1）：token 估算逼近阈值（如 70%）时自动触发 LLM 摘要（我们有 total_tokens 与估算基础）
- **B3 选择性上下文组装**（P2）：不完全全量回放历史，而是"最近 N 步 + 与当前任务相关文件片段"（参考 CLAUDE.md / project context 思路），大改省 token
- **B4 工具输出降噪**（P1）：bash/grep 大输出已截断；再加"尾部优先"策略——命令输出通常关键信息在尾部（错误/结果）

### C. 交互与权限
- **C1 权限确认模式**（P2，可选）：危险操作/目录外操作时询问用户，与黑名单并存
- **C2 /model 热切换 + /status 显示当前模型**（P1）：分层（flash/pro）在会话中随时切
- **C3 /permissions**（P2）：查看/扩展黑名单与围栏

### D. 质量与复盘
- **D1 /review**（P2）：复用 judge——让 agent 自查改动（跑测试 + 质量维度自评），提交前把关
- **D2 /export**（P2）：导出会话/轨迹 JSON（可直接喂给评测/演示）
- **D3 /cost /tokens**（P1）：实时显示步数/耗时/token（数据已在 total_tokens/trajectory）

### E. 工程化（参考 claw-code-agent）
- **E1 工具按需裁剪**（P2）：`coding-agent run "..." --tools read_file,edit_file,bash` 只暴露需要的工具，省 token、防误用
- **E2 保持轻依赖**（持续）：当前仅 openai + python-dotenv，评估去 dotenv（stdlib 读 .env）

## 4. 优先级与 spec-driven 落地路径

| 批次 | 功能 | 依赖/理由 |
|---|---|---|
| **P0** | A1 REPL + /help /exit /clear /compact /status；B1 LLM 摘要 compact | 直接改变使用方式；复用现有 loop/parser/history；演示视频可展示交互 |
| **P1** | A2 /resume 会话持久化；A3 /task；B2 自动 compact；C2 /model；D3 /cost | 在 REPL 上叠加，体验完整 |
| **P2** | C1 权限确认；C3 /permissions；B3 选择性组装；B4 尾部优先；D1 /review；D2 /export；E1 工具裁剪 | 独立增强，按需做 |

每个功能按 spec-driven 落地：先写 `specs/cli.md`、`specs/compact.md`、`specs/session.md` 等（接口+可自动验证的验收标准），再写契约测试（红），再实现（绿）。

## 5. 推荐下一步

**先做 P0：交互式 REPL（slash 命令框架）+ /compact（LLM 摘要）+ /status**。
理由：① 直接把"命令行一次性调用"升级为"交互式 agent"，是演示视频最能出效果的变化；② 复用现有组件多（loop/parser/history/termination/total_tokens），新增面可控；③ /compact 是 Claude Code 语境管理的核心，面试可讲"我们如何解决长会话上下文衰减"。之后按 P1→P2 逐批推进。
