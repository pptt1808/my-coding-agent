# JTBD (Jobs-to-be-Done) — product clarity

Use when the user asks to build or demo a product/feature but the goal is fuzzy.

1. Ask ONE question: what is the user (the "job") really trying to get done — in their own words?
2. Ask what happens today that's painful / when it fails / when they'd switch.
3. Distill into a JTBD statement: "When <situation>, I want to <motivation>, so I can <outcome>."
4. Write the JTBD + the audience + ONE success criterion before any implementation.

Keep it to 2-3 questions, then stop — do not over-interrogate.
